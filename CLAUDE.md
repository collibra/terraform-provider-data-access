# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Terraform provider for Collibra Data Access. It manages access-control resources (grants, filters, masks, filter rules, grant categories, data sources) against a Collibra environment via the `github.com/collibra/data-access-go-sdk` client. Built on the HashiCorp terraform-plugin-framework (protocol v6).

## Commands

```bash
go build -v .                 # build the provider binary
make lint                     # golangci-lint run + go fmt
make fix-lint                 # go fmt + golangci-lint run --fix
make generate                 # go generate ./... (regenerates docs + enumer code)

# Acceptance tests hit a live Collibra environment and require credentials.
make testacc                              # TF_ACC=1, all tests via gotestsum
TF_ACC=1 go test ./internal/ -run TestAccGrantResource -v   # single test
```

Acceptance tests need these env vars set (see `internal/provider_test.go`):
`TF_VAR_collibra_user`, `TF_VAR_collibra_secret`, `TF_VAR_collibra_url`. Without `TF_ACC=1` the `resource.Test` cases are skipped. There are no unit tests separate from acceptance tests — nearly all `*_test.go` files are `TestAcc*` cases against the real API.

CI (`.github/workflows/`) runs build + `golangci-lint` + `go generate` diff check + SonarQube/FOSSA on every PR, then acceptance tests across Terraform 1.10–1.14 (one version at a time, `max-parallel: 1`).

## Architecture

Entry point `main.go` serves `internal.New(version)`. The provider (`internal/provider.go`) authenticates the SDK client with url/user/secret and passes it as both `ResourceData` and `DataSourceData`. To register a new resource or data source, add its constructor to `Resources()` / `DataSources()` in `provider.go`.

### The generic access-control base (most important pattern)

`internal/access_control_resource.go` defines `AccessControlResource[T, ApModel]`, a generic base implementing the full CRUD + import + validation lifecycle shared by every access-control resource. `grant_resource.go`, `filter_resource.go`, `mask_resource.go`, and `filter_rule_resource.go` each **embed** this base and specialize behavior — they do not reimplement CRUD.

Each concrete resource:
- Defines a model struct that embeds/exposes an `AccessControlResourceModel` (id, name, description, state, who, ABAC who-rules, locks).
- Satisfies the `AccessControlModel[T]` interface: `ToAccessControlInput` (model → SDK input), `FromAccessControl` (SDK object → model), plus owner accessors. This pair is where per-resource translation to/from the SDK lives.
- Registers optional hooks on the base: `ReadHook`, `ValidationHook`, `PlanModifierHook` — use these to add resource-specific behavior instead of overriding lifecycle methods.

When adding a new access-control resource, follow this embed-and-implement pattern rather than writing standalone CRUD. Standalone resources/data sources that are *not* access-control (e.g. `data_source_resource.go`, `user_datasource.go`) implement the framework interfaces directly.

### Packages

- `internal/` — provider, resources, data sources. Files are named `*_resource.go` / `*_datasource.go` with matching `*_test.go`.
- `internal/types/` — shared domain constants (e.g. global permissions).
- `internal/types/abac_expression/` — ABAC (attribute-based access control) expression model + enumer-generated operator enums. The `*_enumer.go` files are generated (`//go:generate ... enumer`); edit the `//go:generate` directive in `models.go` and run `make generate`, never edit the `_enumer.go` files by hand.
- `internal/utils/` — small generic helpers (`Ptr`, `Coalesce`, `Map`, string/set conversions). Prefer these for the recurring pointer/slice/`types.Set` conversions the framework requires.

### Docs generation

`docs/` is generated by `tfplugindocs` from `templates/` + `examples/` during `go generate`. Do not hand-edit `docs/`; change `templates/` or `examples/` and regenerate. CI fails if `go generate ./...` produces a diff, so regenerate and commit after changing schemas, examples, or templates.

## Conventions

- Return `diag.Diagnostics` and append errors (`diagnostics.AddError(...)`) rather than returning `error` from resource logic; check `HasError()` before proceeding — this matches the terraform-plugin-framework flow.
- Lint is strict (`.golangci.yml`, `default: none` with a large enable list including `wrapcheck`, `wsl_v5`, `gocritic`, `exhaustive`, `gosec`). Wrap errors and mind formatting/whitespace rules; run `make fix-lint` before committing.
